# Powderline physical-device QA

Automated Chromium viewport testing is useful but is **not** evidence that iOS,
Safari, WKWebView, thermal behavior, or real touch ergonomics work. Tyler should
record each physical test below and attach screenshots or a short screen capture
to the relevant Linear issue when a defect is found.

## Start a phone/tablet test from Windows

1. Connect the Windows PC and device to the same private network.
2. Install `mkcert` once with `winget install FiloSottile.mkcert`.
3. Run `npm run setup:https`. This creates ignored certificate files under
   `.cert/` for localhost and the PC's active LAN IPv4 addresses.
4. Install the mkcert root CA on the device. On iOS/iPadOS, install the profile,
   then enable it under **Settings → General → About → Certificate Trust
   Settings**. Only trust a CA you generated on your own computer.
5. If Windows asks, allow Node.js on **Private networks** only. If no prompt
   appears, add a private inbound firewall rule for TCP 5173.
6. Run `npm run dev:https` and open the printed `https://<LAN-IP>:5173/` Network
   address. Do not use the LAN HTTP address for WebGPU testing.
7. Open `?debug=1&seed=424242` and record the F3 canvas/DPR/performance values.

The fallback certificate generated by Vite is convenient for desktop testing
but is not reliably trusted or hostname-valid on phones. The mkcert workflow is
the repeatable physical-device path.

## Current simulated evidence

`npm run qa:mobile` runs production WebGPU in desktop Chromium with mobile input
emulation. It covers 320×568@2, 430×932@3, 820×1180@2, and 667×375@2, rotates
each profile, rotates while paused, verifies explicit background resume, checks
44 px controls, validates the unsupported-WebGPU screen, and keeps the backing
canvas at or below roughly one megapixel. Reports and screenshots are written to
ignored `tools/reports/mobile-lifecycle/`.
